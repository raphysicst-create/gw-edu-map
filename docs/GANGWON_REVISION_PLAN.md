### 2026-09-25 사용자 확정 사항

- 이 저장소는 전북 교육지도의 업스트림을 포크한 **강원 전용** 저장소다. 전북 버전의 동시 운영·빌드 호환성은 유지 목표에 포함하지 않는다.
- 운영 주체는 개인이며, **업무 참고용 도구**로 표시한다. 교육청 공식 서비스로 표현하지 않고 공식 로고를 기본 적용하지 않는다. 서비스명은 ‘강원 교육지도’를 사용한다.
- 사용자가 보유한 강원 원자료는 없다. 공식 공개 경로에서 수집하는 작업부터 시작한다.
- 실행 결과와 미확보 자료는 `docs/GANGWON_IMPLEMENTATION_STATUS.md`에 기록한다. 아래 계획의 ‘미확보’ 표기는 계획 작성 시점의 상태이며, 실제 취득 여부는 출처 등록부와 실행 기록을 따른다.

## 1. 목표와 확정 요구사항

전북 교육지도를 강원특별자치도교육청 업무에 활용할 수 있는 강원 교육지도로 개정한다. 기존 프로젝트의 화면 구성, 지도 표현, 학교 탐색, 시군 비교, 시계열, 교육문제 탐색, 정적 데이터 생성·검증·배포 방식을 유지한다.

사용자가 지정한 데이터 출처는 **강원특별자치도교육청, 강원특별자치도청 또는 국가기관**으로 한정한다. 화면에 표시하는 통계, 학교 주소·좌표, 경계, 기관 명단, 정책 근거, 배경지도, 건물까지 적용한다. 출처를 확보하지 못한 값을 다른 지역 자료·민간 자료·추정값으로 채우지 않는다.

이번 문서는 개정 범위와 실행 순서를 확정하기 위한 계획서다. 계획 작성이 데이터 확보나 실제 배포 완료를 뜻하지 않는다.

### 완료 목표

- 강원 18개 시군과 초·중·고·특수학교를 대상으로 기존 기능을 제공한다.
- 기존 18개 지표와 10개 교육문제의 구현 범위를 모두 추적하고, 허용 출처와 충분한 자료를 확보한 항목을 공개한다.
- 과거 자료가 확보되는 지표는 기존과 같은 연도별 추이를 제공한다.
- 모든 공개 값에서 원자료의 제공기관·기준일·집계 범위·가공 방법을 추적할 수 있다.
- 전북 학교, 수치, 정책 문구, 좌표, 출처가 강원 배포 산출물에 섞이지 않는다.
- 필수 자료 미확보로 일부 기능이 보류되면 ‘제한 공개’로 구분한다. 기존 기능 전체를 복원하지 못한 상태를 ‘전체 개정 완료’라고 보고하지 않는다.

### 3.1 허용 판단

| 분류 | 처리 원칙 |
|---|---|
| 강원교육청 본청 공식 게시 자료·공식 제공 파일 | 허용. 문서·파일별 기준일과 범위를 확인 |
| 강원도청 공식 게시 자료·공식 제공 파일 | 허용. 도 단위 총괄 자료와 일부 지역 자료를 구분 |
| 중앙행정기관·소속 국가기관이 공식 제공한 자료 | 허용. 제공기관 정보와 원문을 함께 보관 |
| 교육청 소속 교육지원청·직속기관 자료 | 공식 조직 소속과 공식 게시 경로가 확인된 자료만 교육청 계통으로 등록. 관계가 불명확하면 보류 |
| 공공데이터포털 | 유통 경로로만 판단. `data.go.kr`에 있다는 이유만으로 허용하지 않고 실제 제공기관 확인 |
| 정부 공식 위탁 서비스 | 국가기관의 공식 제공 자료라는 근거와 해당 서비스 연결 관계를 등록한 경우만 사용 |
| 공공기관·정부출연연구기관 명의 자료 | 국가기관과 같은 것으로 자동 간주하지 않음. 허용 기관의 공식 제공·게시 근거가 없는 자료는 채택하지 않음 |
| 개인 GitHub, 민간 지도, 언론·블로그·위키, 출처 없는 수작업 목록 | 데이터 원천으로 사용하지 않음 |
| 개별 시군청·학교 홈페이지의 독립 자료 | 지정된 출처 범위에 자동 포함하지 않음. 허용 기관이 공식 취합·제공한 자료를 우선 확보 |

기존 KESS 파일과 한국교육시설안전원 위치 파일은 재사용을 자동 확정하지 않는다. 기존 파서 자체는 재사용할 수 있지만, 데이터 채택은 위 조건을 별도로 충족해야 한다. 교육부·강원교육청의 공식 제공 근거가 실제 파일에 연결되면 그 관계를 기록하고, 그렇지 않으면 해당 기관이 직접 제공한 자료로 교체한다. 단순 외부 링크 소개는 특정 파일의 공식 제공 근거로 충분하지 않다.

### 3.2 출처 등록부

신규 `data/sources/gangwon/source-register.json`에 다음 정보를 관리한다.

| 필드 | 의미 |
|---|---|
| `sourceId`, `providerName`, `providerType` | 자료 식별자·실제 제공기관·허용 기관 분류 |
| `title`, `landingUrl`, `downloadUrl`, `officialEvidenceUrl` | 문서명·공식 소개·직접 수집 경로·기관 관계 근거 |
| `referenceDate`, `publishedAt`, `retrievedAt` | 데이터 기준일·게시일·실제 취득일 구분 |
| `scope`, `coveredRegions`, `schoolLevels`, `fields` | 대상 범위·포함 지역·학교급·수록 항목 |
| `license`, `redistribution`, `storagePolicy` | 원문 및 가공본의 이용·재배포·저장 조건 |
| `sha256`, `parserVersion`, `profileId` | 취득 원본 무결성·가공 코드 버전·지역 |
| `reviewStatus`, `limitations` | 검토 상태·누락과 해석 한계 |

문서 작성 시 아직 취득하지 않은 파일에는 해시나 취득일을 만들어 넣지 않는다. `candidate` → `page-verified` → `acquired` → `validated` → `publishable`을 구분하며, 배포에는 `publishable` 자료만 사용한다. 기관 검토는 도메인 패턴 검사를 보완하며, 이를 대체하지 않는다.

**좌표 확보의 별도 제약:** 국토교통부 [지오코더 API](https://www.data.go.kr/data/15101106/openapi.do)의 현재 안내에는 결과 저장 제한이 명시되어 있다. 따라서 이 API로 좌표를 일괄 변환해 `schools.json`에 저장하는 계획을 기본 해법으로 채택하지 않는다. 저장·재배포가 허용된 정부 공간파일 또는 강원교육청의 좌표 제공 자료를 먼저 확보한다. 허용 조건을 충족하지 못하면 좌표는 결측으로 유지한다.

자료가 없는 경우에는 필요한 항목·기준일·형식·이용 목적을 정리한 자료 요청 초안을 준비한다. 실제 기관에 문의나 요청을 발송하는 일은 이번 계획 작성 범위에 포함하지 않는다.

## 5. 지역·학교 식별 체계

### 5.1 지역

대상은 춘천·원주·강릉·동해·태백·속초·삼척의 7개 시와 홍천·횡성·영월·평창·정선·철원·화천·양구·인제·고성·양양의 11개 군이다. 구현 착수 시 공식 코드집과 대상 목록을 대조한다.

- `gangwon` profile을 추가하고 18개 시군 및 강원 전체 집계 코드를 등록한다.
- 행정표준코드와 통계지역코드를 같은 것으로 취급하지 않는다. 경계 공급자의 코드를 내부 지역 코드에 명시적으로 연결한다.
- 과거 `강원도`와 현재 `강원특별자치도`, 과거·현재 지역 코드의 대응은 공식 개편 근거와 함께 관리한다.
- 시군과 교육지원청 관할은 별도 축으로 둔다. 복수 시군을 관할하는 지원청의 합계를 시군별 값으로 임의 복제·분할하지 않는다.
- 행정동·법정동·읍면동 명칭을 구별하고 경계 레이어 종류를 화면과 메타데이터에 밝힌다.
- 과거 경계를 최신 기준으로 재집계하는 경우 공식 대응표와 계산 방법을 기록한다. 비교 범위가 다르면 시계열 단절로 표시한다.

### 5.2 학교

- 학교명보다 공식 학교 식별자를 우선한다. 출처별 코드 체계가 다르면 대응표를 둔다.
- 기존 `kediCode`의 필수 의존성을 점검하고 `sourceSchoolIds` 등 출처별 식별자 매핑을 추가한다. KEDI 코드가 없는 공식 자료에 임의 KEDI 코드를 부여하지 않는다.
- 명칭 변경·통합·이전·본분교·휴교·폐교를 구분한다. 단순 이름 유사도로 자동 합치지 않는다.
- 불가피한 수동 연결에는 양쪽 공식 원문, 주소, 학교급, 본분교, 적용 시점과 검토 근거를 남긴다.
- 학교명만 확인되는 모호한 연결은 보류한다. 행을 조용히 버려 학교수와 학생수가 맞는 것처럼 만들지 않는다.
- 통계 귀속 시군과 실제 좌표가 위치하는 시군이 다르면 두 정보를 기록하고 사유를 확인한다. 좌표만으로 공식 통계 귀속을 덮어쓰지 않는다.

### 공통 집계 규칙

1. 학교급은 기존 초·중·고·특수 범위를 유지한다. 원본의 유치원·각종학교는 식별해 분리하며 자동 포함하지 않는다.
2. 본교수와 분교를 포함하는 학생 합계는 서로 다른 집계 단위다. 지표마다 포함 규칙을 문서화한다.
3. 지역 비율의 도 전체 값은 분자·분모를 합쳐 다시 계산한다. 시군 비율의 단순 평균을 사용하지 않는다.
4. 원자료의 `0`, 결측, 비공개, 해당 없음, 미수록을 구별한다. 공개하지 않은 작은 수를 역산하지 않는다.
5. 현재 `aggregate.ts`는 일부 합계에서 `null`을 0으로 더한다. 완전성 정보를 추가해 누락을 포함한 합계를 전체 값으로 공개하지 않도록 수정한다. 필요한 경우 확인된 부분합과 수록률을 별도로 제공한다.
6. 2022~2026은 5개 연도 관측치이지만 두 끝점의 경과기간은 4년이다. 화면에는 실제 `2022→2026`을 표시하고, 원자료가 부족하면 존재하지 않는 연도를 보간하지 않는다.
7. 기존 특수교육 지표의 통합 범위와 교육문제 화면의 분리 범위를 유지한다. 한 자료만 확보한 상태에서 합계를 완성하지 않는다.
8. 학생 60명 기준은 기존 탐색 기준으로 유지한다. 강원교육청의 공식 작은학교 지정 기준이 다르면 별도 개념으로 설명한다.

자료 미확보 지표는 등록 항목을 추적하되 `unavailable`과 사유를 노출한다. UI만 숨기는 것으로 끝내지 않고 로더·manifest·URL 파서가 일관되게 처리하도록 변경한다. 누락된 파일을 정상 자료처럼 취급하거나 오류를 통째로 무시하지 않는다.

## 8. 데이터 파이프라인 개정

### 8.1 처리 순서

```text
공식 출처 등록·원본 취득
  → 제공기관·저장/재배포 조건·기준일 확인
  → 지역 및 학교 식별자 정규화
  → 시군·읍면동 경계 생성
  → 학교별 통계·좌표 결합
  → 지표·시계열·폐교·교육문제 생성
  → 출처/정합성/완전성 검증
  → public/data 정적 산출물 확정
  → 앱 빌드·브라우저 검증·배포
```

기존 `data:build`의 단계별 실행 방식과 `data:validate` 최종 관문을 유지한다. `data:kess`는 기존 호환 명령으로 남길 수 있지만 강원 원본이 다른 형식이면 내부 통계 입력 어댑터로 분기한다. 파일 내용이 다른데 확장자나 이름만 KESS 형식으로 바꾸지 않는다.

### 8.2 저장 경로와 지역 혼합 방지

제안 구조:

```text
data/raw/gangwon/<sourceId>/<referenceDate>/...
data/interim/gangwon/...
data/manual/gangwon/...
data/sources/gangwon/source-register.json
src/lib/profiles/gangwon.ts
src/lib/profiles/gangwon/issues.ts
public/data/...                  # 선택한 한 지역의 검증된 결과
```

- 원본과 중간자료를 profile별로 분리한다. 기존 전북 중간 파일을 강원 처리의 fallback으로 사용하지 않는다.
- 원본은 현행처럼 Git 제외를 기본으로 하되, 취득 메타데이터·체크섬·허용된 가공 결과는 추적한다.
- `manifest.json`에 `profileId`, 스키마 버전, 데이터 버전, 기준연도, 출처 ID와 기능별 제공 상태를 추가한다.
- 학교·교육문제·경계 산출물에도 지역 및 데이터 버전을 연결한다. 클라이언트는 다른 profile의 파일을 발견하면 구체적인 갱신 안내와 함께 로드를 중단한다.
- 임시 출력 디렉터리에서 검증한 뒤 활성 산출물로 교체한다. 중간 실패 시 기존 정상 배포 자료를 반쯤 덮어쓰지 않는다.
- 강원 전환 시 남는 전북 읍면동 파일·퇴역 지표 파일을 산출물 목록과 대조해 제외한다. 작업 폴더 밖을 대상으로 하는 광범위 삭제는 하지 않는다.
- 코드·manifest·정적 파일의 캐시 버전이 일치하도록 URL 버전 또는 데이터 버전 경로를 사용한다. manifest와 핵심 상태 파일은 재검증하도록 유지한다.

### 8.3 경계·좌표

- 개인 GitHub 다운로드 의존성을 제거하고 정부 직접 제공 파일을 입력한다.
- SHP 등 입력을 사용할 경우 실제 좌표계를 확인한 뒤 앱의 경위도 좌표계로 변환한다. 좌표계 이름만 바꾸는 처리는 금지한다.
- 시군구 경계를 사용할지 행정동을 합칠지 공급 파일의 체계에 맞춰 결정한다. 통계코드의 일부 자릿수를 잘라 행정코드로 추정하지 않는다.
- 원본·가공 경계의 면적·범위·인접관계·다중 폴리곤·해안·접경 지역을 비교한다. 단순화로 도형이 사라지거나 틈이 생기지 않게 한다.
- 학교 좌표가 없으면 검색·집계·대체 상세에는 남기고 지도 점은 생성하지 않는다. 좌표 확보율과 미확보 사유를 보고한다.
- 특수학교도 동일한 공식 출처 규칙을 적용한다. 민간 지도 검색 결과를 복사해 보충하지 않는다.
- 수동 보정은 원문 근거가 있는 학교 대응·코드 대응에 한정한다. 라벨 위치 이동은 표시용 가공이며 학교의 실제 좌표와 분리한다.

## 10. UI와 지도 개정 기준

- 기존 데스크톱의 지표·설정 상시 노출, 모바일의 접이식 설정과 하단 패널을 유지한다.
- 18개 시군을 화면에 맞추고 춘천·원주·강릉 같은 도심 및 접경·산간 지역에서 확대·축소·학교 선택을 검증한다.
- 기존 표시 규칙인 학생 밀도, 학교 규모·색상, 시군 집계를 유지한다. 실제 줌 임계값 조정이 필요하면 화면 검증 근거를 남긴다.
- 모든 지도·학교 목록·상세·통계가 동일한 필터와 지표 정의를 공유한다.
- 좌표 결측은 학생수 0이나 학교 없음으로 표시하지 않는다.
- 기존 URL의 지표 의미는 유지한다. 전북 지역코드·학교 ID가 들어오면 강원 기본 보기로 안전하게 복귀시키고 다른 학교에 잘못 연결하지 않는다.
- 저장된 지도 설정은 지역 식별자를 포함해 충돌을 막는다.
- 범례·학교 상세·시계열에는 값의 기준일과 출처를 제공한다. 지도 경계 기준일은 교육통계 기준일과 구분한다.
- 기관 수·교사 수만으로 교육 서비스의 충분성이나 효과를 단정하는 문구를 사용하지 않는다.
- WebGL 실패·그래픽 손실·건물 API 오류에서도 학교 검색·통계·상세 확인이 가능해야 한다.

## 11. 검증 계획과 합격 기준

### 11.1 출처·데이터 검증

| 검사 | 합격 기준 |
|---|---|
| 허용 기관 | 공개 데이터와 파생값에 연결된 모든 원천이 허용 정책 충족 |
| 원문 추적 | 모든 공개 출처에 기관·URL·기준일 또는 공식 확인일·범위·변환 이력 존재 |
| 이용 조건 | 저장·가공·재배포·캐시 사용이 자료별 조건에 부합 |
| 지역 범위 | 기본 지표에 강원 18개 시군과 도 전체 행 존재. 미수록은 명시적 결측 |
| 지역 혼합 | 강원 공개 파일에 전북 학교·기관·정책·잔존 읍면동 파일 없음 |
| 학교 ID | 중복·모호한 연결 없음, 집계 대상의 제외·포함 사유 추적 가능 |
| 공식 합계 | 동일 기준일·학교급·운영상태·교원 정의의 공식 강원 집계와 일치 |
| 통계 불일치 | 차이를 0으로 맞추거나 숨기지 않음. 범위 차이 조정표를 만들고 동일 정의로 재검증 |
| 좌표 | 유효 범위·좌표계·공식 주소 매칭 검증, 미확보율과 오류 목록 보고 |
| 폐교 | 등재 전체·미활용 부분·기준일·최근 기간을 분리, 부분 자료로 전체 비율 생성 없음 |
| 시계열 | 각 연도 출처 존재, 모집단 일치 또는 단절 표기, 임의 보간 없음 |
| 결측 | 결측을 실제 0으로 바꾸는 공개 경로 없음 |
| 재현성 | 동일 원본·코드로 재생성 시 데이터 내용 동일. 생성시각 등 메타데이터 차이는 별도 |

공식 비교 값이 없는 항목은 ‘공식 대조 통과’로 기록하지 않는다. 내부 합계 검증과 외부 공식 대조 여부를 별도로 보고한다.

### 11.2 자동 검사

기존 단위·컴포넌트·파이프라인·Playwright 테스트를 유지하고, 강원 시나리오와 새 출처 정책을 검증한다. 화면 문구만 단순 교체한 테스트로 충분하다고 보지 않는다.

- 전북 파일을 강원 처리에 넣었을 때 실패하는 검사.
- 허용되지 않은 제공기관, 출처 누락, 기준일 누락의 배포 차단 검사.
- 정부 경계의 좌표계·코드 매핑과 18개 지역 도형 검사.
- 학생수 누락·분모 0·본분교·휴교·특수학교 포함 범위의 집계 검사.
- 학교 코드 변경과 동명이교의 오연결 방지 검사.
- 미활용 명단만 존재할 때 전체 폐교 지표가 생성되지 않는 검사.
- manifest/profile/version 불일치와 부분 빌드 실패 복구 검사.
- 제공 불가 지표·주제의 URL, 범례, 로더 처리 검사.

기존 명령: `npm run data:validate`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run e2e`.

### 11.3 브라우저·운영 검증

1440×900, 1024×768, 390×844, 360×640에서 학교 검색·선택·해제, 지역 전환, 18개 지표, 10개 주제의 상태, 시계열, URL 복원, 모바일 포커스와 가로 넘침을 검사한다. 학교 좌표 없음, 데이터 요청 실패, WebGL 미지원·손실, API 키 없음·요청 실패도 포함한다.

실제 VWorld 키로 건물·배경지도 동작을 별도 검증한다. fixture 기반 테스트 통과를 실제 API 검증으로 보고하지 않는다. 소프트웨어 GPU나 모바일 크기 에뮬레이션 결과를 실제 휴대전화 성능으로 일반화하지 않는다. 강원의 넓은 범위에서 초기 로드량·타일 캐시·반복 이동 후 메모리를 기존과 같은 조건으로 비교한다.

## 14. 운영·갱신·배포 방침

- Node.js 22를 기준으로 개발 환경을 맞춘다. 현재 분석 환경의 Node.js 24를 프로젝트의 검증 완료 버전으로 간주하지 않는다.
- 강원 빌드와 개발·운영 환경의 `NEXT_PUBLIC_EDU_MAP_PROFILE` 및 데이터 빌드 profile을 일치시킨다.
- 통계 최신연도는 확보 자료로 결정하며 환경변수만 바꿔 기준연도를 올리지 않는다.
- 공개 주소는 `NEXT_PUBLIC_SITE_URL`에 설정한다. 배경지도 공개 키와 건물 서버 키는 분리하고 로그·저장소에 비밀키를 넣지 않는다.
- 지표·학교·교육문제·경계는 검증한 버전을 함께 배포한다. API를 실시간 호출하는 건물은 통계 기준일과 별개로 설명한다.
- 원본 갱신 시 제공기관·스키마·기준일·포함 범위·학교 식별자 변경을 먼저 확인하고 재생성한다.
- 갱신 보고에는 원본 변경, 값 변경, 신규·제외 학교, 누락 자료, 검증 결과를 기록한다.
- 실패 시 이전의 검증된 강원 코드·데이터 버전으로 되돌린다. 전북 데이터를 강원 복구본으로 사용하지 않는다.
- 운영 일정에 맞춘 갱신 주기는 자료별 공식 공표 주기를 확인한 뒤 설정한다. 이번 문서 작성으로 자동 수집이나 예약 실행을 생성하지 않는다.
